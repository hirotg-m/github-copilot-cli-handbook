# GH-300 対策: GitHub Copilot CLI で実践すること

このガイドは、GH-300: GitHub Copilot の学習で、GitHub Copilot CLI を実際に操作して身に付ける項目をまとめたものです。`copilot` コマンドを実行でき、認証済みであることを前提にします。

試験の出題範囲は更新されるため、受験前には必ず [Microsoft Learn の GH-300 学習ガイド](https://learn.microsoft.com/ja-jp/credentials/certifications/resources/study-guides/gh-300) で最新のスキル測定項目を確認してください。このガイドは試験問題や正解を再現するものではありません。

## 1. 安全な練習環境を用意する

本番環境、機密情報を含むリポジトリ、共有ブランチでは練習しません。内容を理解している小さなサンプルリポジトリで作業用ブランチを作成します。

```bash
git status
git switch -c gh-300-copilot-cli-practice
copilot
```

初回に表示されるディレクトリの信頼確認と、ファイル変更・コマンド実行時の許可画面を確認します。Copilot CLI は許可された範囲でツールを使うため、各操作の対象と影響を確認してから許可します。

## 2. CLI の基本操作を説明・実行できるようにする

GH-300 の学習ガイドでは、Copilot CLI の目的、インストール手順、主要な機能とコマンド、対話的な利用とセッション操作が対象です。次の操作を自分で実行し、何ができるか説明できる状態を目指します。

```bash
copilot version
copilot help
copilot
```

対話セッションでは、少なくとも以下を確認します。

```text
/help
/diff
/review
/context
/session
```

すべてのコマンドを暗記するのではなく、`/help` で確認できること、`/diff` で作業ツリーの差分を確認できること、`/review` で変更のレビューを依頼できることを理解します。ログイン状態の確認や切り替えが必要な場合は、`/login` と `/logout` も試します。

## 3. リポジトリの文脈を与えて調査させる

良い結果には、目的、対象、制約、完了条件を含む具体的なプロンプトが必要です。まず、変更を伴わない調査で文脈の渡し方を練習します。

```text
README.md と src/ を確認し、このリポジトリの目的、実行方法、テスト方法を説明してください。ファイルの変更やコマンド実行はしないでください。
```

特定のファイルを会話に含めたい場合は、`@` に続けてファイルを指定します。例えば、`@README.md` を入力して候補からファイルを選択します。

次の要素を変えながら、回答の精度を比較します。

1. 曖昧な依頼と、対象ファイルを指定した依頼
2. 要件だけの依頼と、入出力例・制約・完了条件を含めた依頼
3. 一度の大きな依頼と、調査、計画、実装、確認に分けた依頼

回答が不十分な場合は、推測で実装を進めさせず、不足している前提や確認すべきファイルを質問します。

```text
実装はまだ行わず、この要件を満たすために不足している情報と確認すべきファイルを挙げてください。
```

## 4. スクリプト生成とファイル管理を練習する

CLI の対象には、スクリプト生成とファイル管理が含まれます。小さく、確認しやすい作業を依頼します。

```text
logs/ 配下の .log ファイルを日付別に集計する bash スクリプトを scripts/summarize-logs.sh に追加してください。標準入力ではなく引数でディレクトリを受け取り、存在しないディレクトリではエラー終了してください。変更前に実装方針を示し、変更後に使い方を説明してください。
```

生成後は、内容を読んでから次を実行します。

```bash
git diff --check
git diff
```

続けて、境界条件を含む確認項目を提案させます。

```text
このスクリプトの正常系、空のディレクトリ、不正なパス、スペースを含むファイル名について、確認手順を提案してください。ファイルは変更しないでください。
```

## 5. コード、テスト、ドキュメントの生成を一巡させる

同じ小さな機能について、実装だけでなくテストと説明も依頼します。各段階で結果を確認することが重要です。

```text
<対象の関数または機能> に対して、境界値と異常系を含むテストケースを提案してください。既存のテストの書式に従い、変更前に対象ファイルとテスト観点を説明してください。
```

```text
今回の変更を利用者向けに説明する README の追記案を作成してください。前提条件、実行例、失敗時の対処を含めてください。まず差分案だけを示してください。
```

提案を採用する場合は、変更対象を限定して実装を依頼し、差分を確認します。Copilot の出力は常に正しいとは限らないため、コンパイル、テスト、実行結果を自分で確認します。

## 6. レビュー、セキュリティ、責任ある利用を実践する

Copilot の出力には、もっともらしい誤り、古い API の使用、脆弱性、ライセンスや機密情報に関する懸念が含まれる可能性があります。生成結果を無条件で採用しないことを習慣にします。

変更を作成したら、次のように依頼します。

```text
現在の差分をレビューしてください。仕様との不一致、例外処理、入力検証、機密情報の露出、依存関係のリスクを優先して確認してください。ファイルは変更しないでください。
```

確認時には、少なくとも次を実施します。

- 要件、既存コード、実行結果と生成物を照合する
- テストで通常入力、境界値、不正な入力、失敗時の動作を確認する
- トークン、パスワード、個人情報、社内限定の情報をプロンプトやコードに含めない
- 提案の出典、ライセンス、公開コードとの一致が問題になる場合は、組織のポリシーに従って確認する

## 7. 設定、データ、プライバシーを説明できるようにする

CLI の操作だけでなく、GH-300 では Copilot が処理するデータ、プロンプトの文脈、出力の制約、プライバシー、コンテンツ除外、公開コードに一致する提案のフィルターなども対象です。これはローカルの CLI 操作だけで完結しない設定を含みます。

次を自分の利用プランと組織ポリシーに照らして確認します。

1. Copilot に送信してよい情報と送信してはいけない情報
2. 組織・エンタープライズで適用されるコンテンツ除外とポリシー
3. 提案が公開コードに一致する場合のフィルターと、出力の確認方法
4. `.github/copilot-instructions.md` などの指示ファイルが応答に与える影響

現在のセッションで読み込まれている指示や設定は、`/instructions` と `/env` で確認できます。設定の可否と場所は、利用プラン、組織の権限、製品の提供状況によって異なります。

## 8. 最後に通し演習を行う

次の依頼を、調査、計画、実装、確認、レビューの順に実施します。各段階で許可内容と差分を確認してください。

```text
<小さな改善要件> を実装したいです。まず関連ファイルを調査し、変更案、影響範囲、確認方法を示してください。実装はまだ行わないでください。
```

提案に納得した後は、対象ファイルと完了条件を指定して実装を依頼します。完了後には、テスト、`/diff`、`/review`、`git diff` を使って結果を確認します。

最後に、次のように依頼して学習内容を振り返ります。

```text
この作業で使用した Copilot CLI の機能、渡した文脈、実施した検証、責任ある利用のために確認した点をまとめてください。
```
