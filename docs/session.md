# GitHub Copilot CLI のセッションを管理する

GitHub Copilot CLI では、`copilot` を起動してから終了するまでの対話がセッションです。セッション内では、それまでの会話、依頼内容、Copilot CLI が確認した情報が文脈として利用されます。このガイドでは、セッションの確認、開始、再開、整理、終了の方法を説明します。

## セッション一覧を確認する

対話セッションで `/session` を実行すると、利用できるセッションを一覧表示して管理できます。

```text
/session
```

一覧から、再開したいセッションを選びます。作業内容が分かる名前を付けておくと、一覧から目的のセッションを選びやすくなります。

```text
/rename ログ集計スクリプトの実装
```

一覧に表示されたセッション ID、タスク ID、または名前を指定して再開することもできます。

```text
/resume <session-id>
```

## 現在のセッションを確認する

現在の会話で使用している文脈の量は `/context`、利用状況は `/usage` で確認します。

```text
/context
/usage
```

### `/context` の見方

`/context` は、現在のセッションでモデルに渡す文脈ウィンドウのトークン使用量と、その内訳を可視化します。会話の本文だけでなく、システム指示、読み込んだファイル、ツールの実行結果など、応答を生成するために参照される情報も文脈に含まれます。

表示される使用量が上限に近いほど、新しい依頼に使える文脈は少なくなります。これは料金や API の利用回数ではなく、現在の会話で参照可能な情報量の目安です。

```text
/context
```

たとえば、次のように表示された場合を考えます。

```text
Context Usage

○ ○ ◌ ◌ ● ◉ ◉ ◉ · ·   gpt-5.6-terra · 35k/400k tokens (9%)
· · · · · · · · · ·   ○ System Prompt           9.4k   (2%)
· · · · · · · · · ·   ◌ System Tools            8.6k   (2%)
· · · · · · · · · ·   ● MCP Tools               1.5k  (<1%)
· · · · · ◎ ◎ ◎ ◎ ◎   ◉ Messages               15.9k   (4%)
◎ ◎ ◎ ◎ ◎ ◎ ◎ ◎ ◎ ◎   · Free Space            223.0k  (56%)
◎ ◎ ◎ ◎ ◎ ◎ ◎ ◎ ◎ ◎   ◎ Buffer                141.6k  (35%)
```

この例では、モデルの文脈ウィンドウは `400k tokens` で、そのうち `35k tokens`、約 9% を使用しています。各行は次の内容を表します。

| 項目 | この例での値 | 意味 |
| --- | ---: | --- |
| `System Prompt` | 9.4k | Copilot CLI の動作や、このリポジトリで読み込まれた指示 |
| `System Tools` | 8.6k | 利用可能な組み込みツールの定義 |
| `MCP Tools` | 1.5k | 設定された MCP サーバーが提供するツールの定義 |
| `Messages` | 15.9k | このセッションでの会話、ファイル内容、ツール実行結果など |
| `Free Space` | 223.0k | 新しい会話やツール結果に使用できる領域 |
| `Buffer` | 141.6k | 応答の生成やセッションの安定した継続のために予約されている領域 |

先頭の記号の並びは、これらの割合を視覚的に示したものです。この例では、`Messages` が現在の文脈使用量の大半を占めています。会話を続けて `Messages` が増え、`Free Space` が少なくなったら、必要な情報を残して `/compact` を実行します。

文脈が大きくなった場合は、現在の作業に必要な判断や未解決事項を指定して `/compact` で会話を圧縮します。別の課題に切り替える場合は `/new` を使い、以前の会話を引き継がずに開始してください。

長い会話では、過去の情報が増えるほど重要な指示を見失ったり、文脈の上限に近づいたりすることがあります。現在の作業に不要な会話が多い場合は、次の手順で整理または新規開始を検討してください。

## 新しいセッションを開始する

`copilot` を起動すると、新しい対話セッションが始まります。

```bash
copilot
```

起動中のセッションで新しい会話を始めるには、`/new` を実行します。

```text
/new
```

過去の会話を引き継がず、現在のセッションを破棄して最初から始める場合は `/clear` を使います。

```text
/clear
```

異なる課題、異なるリポジトリ、機密性が異なる作業は、別のセッションに分けてください。新しいセッションでは、目的、変更してよい範囲、確認方法を改めて伝えます。

## 既存のセッションを再開・切り替える

過去のセッションを再開または切り替えるには、`/resume` を使います。セッション ID、タスク ID、または名前を指定することもできます。

```text
/resume
```

再開後は、作業ツリーが想定どおりかを必ず確認します。セッションの会話履歴があっても、ブランチやファイルの状態は変更されている可能性があります。

```bash
git status
git diff
```

## 長い会話を整理する

会話の要点を保ちながら文脈を圧縮するには、`/compact` を使います。必要であれば、残すべき情報を指定します。

```text
/compact テスト失敗の原因、採用した実装方針、未解決の課題を残してください。
```

圧縮前に、現在の作業内容を要約させておくと、重要な判断を確認できます。

```text
このセッションで変更したファイル、実行した確認、未解決の課題を簡潔にまとめてください。
```

会話履歴を新しい作業に持ち込む必要がない場合は、`/compact` ではなく `/new` を選びます。

## セッションを終了する

対話セッションを終了するには、次のいずれかを使います。

```text
/exit
```

キーボードでは、`Ctrl+D`、または `Ctrl+C` を2回押して終了できます。

終了前に、ファイルの変更と未完了の作業を確認します。

```bash
git status
git diff
```

ファイルの変更はセッションを終了しても自動的にはコミットされません。必要な変更を確認し、テストなどの確認を行ったうえで、自分でステージングとコミットを実施してください。

## 使い分けの目安

| 状況 | 操作 |
| --- | --- |
| 今の会話の文脈量を確認したい | `/context` |
| 会話を要約して継続したい | `/compact` |
| 別の課題を始めたい | `/new` |
| 過去の会話に戻りたい | `/resume` |
| 現在の会話を捨てて始めたい | `/clear` |
| 作業を終えて CLI を閉じたい | `/exit` |
